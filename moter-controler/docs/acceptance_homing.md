## 分かったこと

- #3（後部ヨー）には両端に機械的な止まりがあり、端当て原点復帰がそのまま成立する。ストローク 6160 カウント（2 回の測定で 6159 / 6160）。
- 連続 10 % 駆動での端当ては、encoder-tester の 250 ms パルス法より再現性が高い（端の位置が 1 カウント差）。
- 系統を切り替えると原点が無効になる（設計どおり）。切り替え後は P 端へ をやり直す。
- USB CDC の出力が、次の書き込みまで遅れて届くことがあった（`AUTO cal done` が 20 秒遅れ）。`Serial.flush()` を AUTO / ENC 行の後に入れた。
- 片相断線では計数が止まらない（残った相の揺れや浮いた入力の拾いで 65 count/s）。無パルス停止だけでは検出できず、速度の下限（150 count/s）が必要だった。
- 端当ての到達位置は 0〜16、6155〜6171 の幅でばらつく。押し込みの深さの差。

### 同日、新個体での報告 2 件と対応（ファーム 89d3a8b で記録）

シリアルを 0.5 s ごとに読みながら再現してもらった記録:

- 速度 +1 / +2 ではカウント変化なし（機構が動かない）。**+3 で count 2060 → 11 まで約 6 s かけて減少**（cps −70 → −530 と滑らかに加速、A/B は 00→01→11→10 を巡回）。これは実回転の波形で、ノイズではない。#1 は速度 + で沈む側なので、3 % と重力で下端まで沈んだと解釈する。報告の「動いていないのにカウントが飛ぶ」は、ゆっくり沈んだ分と考えられる。
- 直後に「校正」→ `cal moving pos=2` → 0.3 s で `cal failed stall pos=-4`。既に下端に居る状態から P 端行程を始めたため、猶予 300 ms 後に無パルス、移動量 < 400 で失敗になった（設計どおりの動作だが、端から始められないのは不便）。
- 対応: 端当てで開始直後に止まったら反対へ 600 カウント退避してから改めて当てる（RETREAT_COUNTS、ホストテスト 236 件）。退避でも止まれば失敗。
