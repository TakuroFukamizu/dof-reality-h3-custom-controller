## 分かったこと

- #3（後部ヨー）には両端に機械的な止まりがあり、端当て原点復帰がそのまま成立する。ストローク 6160 カウント（2 回の測定で 6159 / 6160）。
- 連続 10 % 駆動での端当ては、encoder-tester の 250 ms パルス法より再現性が高い（端の位置が 1 カウント差）。
- 系統を切り替えると原点が無効になる（設計どおり）。切り替え後は P 端へ をやり直す。
- USB CDC の出力が、次の書き込みまで遅れて届くことがあった（`AUTO cal done` が 20 秒遅れ）。`Serial.flush()` を AUTO / ENC 行の後に入れた。
- 片相断線では計数が止まらない（残った相の揺れや浮いた入力の拾いで 65 count/s）。無パルス停止だけでは検出できず、速度の下限（150 count/s）が必要だった。
- 端当ての到達位置は 0〜16、6155〜6171 の幅でばらつく。押し込みの深さの差。

### 同日、新個体での報告 2 件と対応（ファーム 89d3a8b で記録）

シリアルを 0.5 s ごとに読みながら再現してもらった記録:

- 速度 +1 / +2 ではカウント変化なし（機構が動かない）。**+3 で count 2060 → 11 まで約 6 s かけて減少**（cps −70 → −530 と滑らかに加速、A/B は 00→01→11→10 を巡回）。これは実回転の波形で、ノイズではない。#1 は速度 + で沈む側なので、3 % と重力で下端まで沈んだと解釈する。報告の「動いていないのにカウントが飛ぶ」は、ゆっくり沈んだ分と考えられる。
- 直後に「校正」→ `cal moving pos=2` → 0.3 s で `cal failed stall pos=-4`。既に下端に居る状態から P 端行程を始めたため、猶予 300 ms 後に無パルス、移動量 < 400 で失敗になった（設計どおりの動作だが、端から始められないのは不便）。
- 対応: 端当てで開始直後に止まったら反対へ 600 カウント退避してから改めて当てる（RETREAT_COUNTS、ホストテスト 236 件）。退避でも止まれば失敗。

### 確認結果（ファーム c76fd59、個体 1C:DB:D4:BA:8D:58、#1）

- +1 を 3 回押して +3: シートがゆっくり沈むことを目視で確認。「カウントが飛ぶ」は実際の沈み込みだった。

### #3 の校正（2026-10-31、個体 30:ED:A0:0B:20:40、ファーム main 9669296）

ケーブルを #3 に差し替え、元の個体 30:ED に main 9669296（usbpower）を書き込んで実施。シリアルを 0.5 s ごとに読みながら記録。

- 書き込み直後の NVS の選択は `#2` で、`#2` 枠は未校正（`cal=0`）。10/26 の #3 の値（6160 / 3080）は `#3` 枠に残っているはずだが、今回 `#3` を選ばなかったので未確認。
- 16:59 に USB が切れた（ホスト側 `Device not configured`）。17:10 に `BOOT` が出てから操作再開。当初は USB 無応答の 3 回目と見たが、3 台構成への配線替えの時間帯なので、ケーブルの抜き差しと考えるのが自然（[multi_axis_20261031.md](multi_axis_20261031.md) の「USB・シリアルについて」）。
- 17:10:21 電源 入 → 17:10:25「下限へ」: 開始 0.3 s で無パルス → 退避も 0.3 s で無パルス → `home failed stall pos=2`（両方向とも count 変化 0）。17:10:33 に再度「下限へ」: 今度は動いて `home done ok pos=4`（5 s、約 −650 count/s）。電源 入 から 4 s では動かず、12 s では動いた。24V の立ち上がり待ちか別の要因かは未確定。退避の猶予は設計どおり 0.3 s（猶予 300 ms と無パルス 200 ms は重なるので、停止判定は開始 300 ms）。
- 17:10:41「校正」: P 端 `pos=4` → N 端 `pos=6129` で `AUTO saved motor=2 stroke=6138 neutral=3069 sign=1` → 中立 `dwell pos=3076` → `done ok pos=3079`（13 s）。6138 は 10/26 の 6160 と 22 差（0.4 %）、符号は同じ +1（速度 + で右へ、カウント負）。
- **保存先は `#2` 枠。** 画面で `#3` に切り替えたとのことだが、シリアルに `OK motor=3` が無く、起動時の選択も `#2` のままだった。切替のタップが効かなかった（電源 入 のまま押して「電源OFFで切替」になった、またはタップが外れた）と考えられる。拒否されたタップはこれまで画面通知（1.2 s）だけだったので、シリアルにも `UI motor_disabled motor= relay= active=` を出すようにした。
- 対応: 電源 切 の状態で `#2` → `#3` に切り替え（シリアルに `OK motor=3 cal=…` が出るのを確認）、「校正」をやり直す。`#2` 枠に入った 6138 / 3069 は #2 系統の値ではないので、`#2` を選んで `UNCAL` で消すか、この個体を #2 に使わない。
