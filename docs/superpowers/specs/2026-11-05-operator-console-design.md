# オペレーター管理画面（設定画面と監視画面）と、再起動なしの設定反映

日付: 2026-11-05。対象: `control-server`（h3-control-server）。
出どころ: 2026-11-02〜05 の会話（ユーザー＝リグの責任者）、`docs/control-server/runs/plan_20261103.md`、`docs/control-server/hardware-bringup.md`、Issue #11 / #15、PR #59。

「ユーザー:」はユーザーが決めたこと、「判断:」は書き手（Claude）が決めたことで、レビューで覆してよい。

## 1. 何のためか

3 軸のモーションシート（H3）を、展示会場でゲーム（STAR SWARMER など）に動かさせる。いまの画面は開発者向けの試験ページ（`GET /`）とジョイスティック試験ページ（`GET /joystick`）だけで、準備と展示中の監視・復旧を任されたスタッフが使う前提になっていない。ターミナルの `curl` や設定ファイルの手書きが、準備の手順の多くを占めている（plan_20261103.md §1〜2）。

この仕事で作るもの:

1. **設定画面**（開場前の準備用）
2. **監視画面**（展示中、ゲームを動かす前・動かしている間）
3. それを成り立たせるサーバーの変更: **校正結果と個体の入れ替え（`device_id`）を、サーバーを再起動せずに反映する**

### 使う人

ユーザー: 中身を知っている人のこともあるが、**その場を任された別のスタッフのこともある**。重要なものは、細かい文字を読まなくても分かるようにする。

### 使う場面

ユーザー: 2 つ。

- 開場前の準備
- 展示中、ゲームを動かす前と動かしている間

ユーザー: 展示中に一番大事なのは、**エラーで止まったときの回復**と、**非常停止のあとのリセット**。

### 使う機器

ユーザー: **ハードウェアにつながった PC だけ。Windows か Mac。** ネットワーク越し・スマホ・タブレットは対象外。

## 2. 目標・非目標・やってはいけないこと

目標:

- 止まったとき、任されたスタッフが「何が起きたか」と「次に何を押すか」を一目でつかめる。
- 準備（USB・接続の確認 → 校正 → 動作確認）を、ターミナルなしで画面だけで進められる。
- M5Stack（CoreS3）を物理的に入れ替えた（故障など）とき、画面からサーバーの設定を直せる。
- 校正や個体の入れ替えのたびに、サーバーを再起動しなくてよい。

非目標:

- ネットワーク越しの操作、スマホ・タブレット対応、複数人の同時操作。
- 物理の非常停止（24 V の遮断）の代わり。画面の「非常停止」は今の `POST /v1/stop`（ブレーキをかけて止める）であり、そのことを画面にも書く。
- ファームの書き込み（esptool / pio）を画面から行うこと。
- 既存の試験ページ・ジョイスティックページの置き換え。判断: 両方とも残す（開発者向け）。

やってはいけないこと（技術的に動いても失敗とみなす）:

- 異常時の表示が小さなバッジだけで、見落とせる。
- 校正（機構が端から端まで動く）を、座席が空かの確認なしに押せる。
- 動いている最中（ARM 中）に、校正値・`device_id` が差し替わる。
- 開いてはいけないポート（他プロジェクトの ESP32-S3 など）を開く。PR #59 の約束を崩さない。
- 接続が切れたのに、最後の値を正常なまま表示し続ける。

## 3. 制約

- サーバーは Rust（axum）。画面は既存ページと同じく `include_str!` でバイナリに埋め込む 1 枚の HTML（外部資源なし、オフラインで動く、日本語 UI）。判断: 新しい依存（フロントエンドのビルド工程）は入れない。
- loopback だけで待ち受ける（`server.bind`）。管理トークンは既定で不要（`require_admin_token = false`）。トークンを有効にした設定でも動くこと（既存ページと同じ `sessionStorage` の扱い）。
- Windows と Mac のブラウザ（Chrome / Edge / Safari の現行版）。フォントは OS にあるものだけ（Mac: ヒラギノ明朝・ヒラギノ角ゴ、Windows: 游明朝・游ゴシック・Meiryo）。フォントファイルを同梱しない。
- 状態は `GET /v1/status`（既存、200 ms 程度のポーリング）と `GET /v1/events?after=`（既存）から取る。判断: WebSocket の新設はしない（必要になったら builder の判断で）。
- 実機は別のセッションが運転していることがある。開発・試験は模擬軸（sim backend と PR #59 の `FakeUsb`）で行い、実機での確認は操作者の OK を取ってから。
- 依存する未マージの PR: #59（`ports = "auto"`、USB シリアル番号で個体を探す）。入れ替えの流れはこれを前提にする。

## 5. 監視画面

### 構図（ユーザーが A 案を選んだ）

ブレインストーミングで 3 案（A: 判定語の帯、B: 座席の図、C: MAGI 風の 3 ブロック）を見比べ、ユーザーは **A** を選んだ。

- 画面の上部を **状態の帯** が占める。帯には大きな判定語（例「異常停止」「稼働中」「待機」）と、短い理由（どの軸が・何で）を出す。
- 帯の下に 3 軸の状態（名前・判定語・位置）。
- 右に、その状態での次の手順と、主要なボタン。

状態ごとの帯（判断: 文言と色の割り当ては builder が調整してよい。原則は「通常時は静か、異常時は面積と塗りが変わる」）:

| rig_state など | 帯 | 判定語の例 | 右の主ボタン |
| --- | --- | --- | --- |
| FAULT_LATCHED | 赤の塗り、上部の約半分 | 異常停止 | 異常をリセット |
| OFFLINE / 軸の未接続 | 中性色＋欠測語 | 接続待機 | 設定画面へ |
| CALIBRATION_REQUIRED | 黄 | 校正が必要 | 設定画面へ |
| READY_TO_ARM | 暗い地・細い帯 | 待機 | ARM |
| HOLDING | 暗い地・細い帯 | 保持 | （ゲームの START 待ち） |
| ACTIVE | 暗い地・細い帯、緑の輪郭 | 稼働中 | 非常停止 |
| STOPPING / BRAKED_DISARMED | 黄 | 停止中 / 停止 | ― |

- 異常の理由は `status.fault` と `fault_history[0]` から、人の言葉にして出す（例: `axis_fault` / `ENCODER_FAULT` / axis 2 → 「#2 左リフト　エンコーダ異常（動かない）」）。元のコード（`ENCODER_FAULT` など）も小さく併記する。
- 復旧の手順の文言（例: 来場者を降ろす → 周りを確認 → リセット）は、原因ごとに書き手が下書きし、ユーザーが直す。判断: 文言は HTML 内の表で持ち、コードに散らさない。
- 非常停止のあとのリセット（ユーザーが一番大事と言った場面）: 画面の非常停止（`/v1/stop`）・M5Stack の画面の非常停止（`LOCAL_ESTOP`）のどちらで止まったかを帯に出し、解除の操作を 1 か所に置く。
- 接続が切れた・status が古い（`status_age_ms` が大きい、ポーリングが失敗）ときは、最後の値を正常のまま出さず、欠測と分かる表示にする。

### 見た目（ユーザー: エヴァンゲリオン風）

`evangelion-console-design` スキルの原則に従う。要点:

- 判定語は太い明朝（ヒラギノ明朝 W6〜W8 / 游明朝 Demibold〜Bold）、機器ラベルは細長い欧文の大文字、数値は等幅数字。本文・ボタンは読めるゴシック。
- 黒地、橙の機器ラベル、緑の輪郭（正常）、赤の塗り面（異常）、黄（注意）。角は直角。影・グロー・常時点滅はしない。
- 色を消しても、判定語・形・数値で状態が分かる。
- `prefers-reduced-motion` では状態の切替を即時に。
- 作品の固有名詞（NERV・MAGI・LCL など）やロゴは使わない。ラベルはこの装置の用語（軸・校正・リミットなど）。

ブレインストーミングの見本（A 案）: `.superpowers/brainstorm/…/content/fault-composition.html`（スクラッチ。リポジトリには入れない）。

## 6. サーバー: 再起動なしで反映する

### いまの作り

- supervisor は起動時に設定から校正値（`cal`）・ハッシュ・`operator_valid` を一度だけ作る（DESIGN.md §11）。
- 校正（CAL_RESULT OK）のあとは、その軸に `calibration_stale` を立てて ARM を止める。消えるのはサーバーの再起動だけ。
- `/v1/calibration/export` は、つながっている個体の `device_id` と校正値を入れた **新しい設定ファイル** を書く（`calibration_valid = false`）。操作者が中身を見て `true` にし、そのファイルで再起動する。

ユーザーの問い（2026-11-05）:「そもそも再起動を不要にできないか」。答え: 安全のための止め方は正しいが、新しい値をその場で入れ直す経路が無いだけ。作る。

### 作るもの

全軸が DISARMED（rig が armed でない、校正中でない）のときに限り、次をその場で行う管理 API:

1. **校正値の反映**: その軸の最新の CAL_RESULT（OK）から、export と同じ計算（`calibration_export::derive`）で値を作る → 設定ファイルに保存 → supervisor の `cal[i]`・ハッシュを差し替え → `calibration_stale` を消す → その軸へ CONFIG を送り直す（既存の `reconcile_config` の経路）。
2. **`calibration_valid` の宣言**: 操作者が「この値はこの軸で測った」と確認したときに true にする（hardware-bringup.md §5 の確認項目を画面に出し、チェックしてから押せるボタン）。設定ファイルにも保存する。
3. **`device_id` の書き換え（個体の入れ替え）**: 軸 N の `device_id` を、画面で選んだ個体の値に変える → 設定ファイルに保存 → supervisor の照合値を差し替え → `ports = "auto"` の探索対象を差し替え（PR #59 の発見タスクが新しい id を探し始め、古い id のポートは開かなくなる）。入れ替えた軸は `calibration_valid = false` に戻す（別の個体なので）。

端の余裕（判断。builder check の指摘）: 運用中の設定は `count_at_virtual_0 / 1023` をソフトリミットから **350 count 内側** に置いている（Issue #34 / PR #38: 下端で 152 count 以上行き過ぎた）。`derive` はここをソフトリミットそのものにするので、そのまま使うと反映のたびに余裕が消える。反映では、**いまの設定の軸ごとの余裕（`count_at_virtual_0 − soft_min_count`、`soft_max_count − count_at_virtual_1023`）を保ったまま** 新しいソフトリミットの内側に置く。既存の export も同じ扱いに揃える。

共通の決まり:

- 設定ファイルの保存は、書く前に検証（`Config::from_toml_str`）、元のファイルを日時つきで残し、一時ファイルに書いてから置き換える。判断: export と同じく、行単位の置き換えでコメントを残す。
- 保存に失敗したら、メモリ上も変えない（ファイルとメモリを食い違わせない）。
- サーバーが設定ファイルから起動していなければ（`--config` なし）、これらは 500 `no_config_path`（export と同じ）。
- 反映した内容はイベントに残す（例 `config_applied {axis, what, before, after}`）。
- 再起動が必要なまま残す項目: `server.*`、`timing.*`、`backend.*`（`ports` 以外）、`power_controller_axis`、軸の名前など。展示中に触らない項目。判断: 画面からは変えない。

### 入れ替えの流れ（設定画面）

1. 故障した個体を外し、予備をつなぐ。
2. 画面に「未登録の個体」（どの軸の `device_id` とも一致しない ESP32-S3。MAC と、対応する device_id）が出る。PR #59 の `unmatched_units` と同じ判定。判断: status に `unregistered_units: [{port, usb_serial, device_id}]` を足す（列挙だけ。開かない）。
   - この一覧には、他プロジェクトの ESP32-S3（扉の鍵の StampS3A など、同じ VID:PID）も並ぶ。判断: 割り当ての前に、**その CoreS3 の画面に出ている `dev XXXX`（MAC の末尾 2 オクテット）を操作者に入力させ、一致したときだけ割り当てる**。一致しなければ開かない。
3. 「この個体を #N に割り当てる」→ §6 の 3。
4. 新しい個体の画面で系統（#N）を選ぶよう案内する（系統は MCU 側で選ぶ。サーバーからは変えない）。
5. その軸だけ校正 → 結果の行程を前の値と比べて ±30 以内かを判定語で出す → 反映（§6 の 1）→ 宣言（§6 の 2）。
6. ARM できる状態に戻る。再起動はしない。

## 7. 設定画面

上から準備の順に並べる（plan_20261103.md §1〜2 を画面にしたもの）。

1. **USB・接続**: 軸ごとに、設定の個体（MAC・device_id）、見えているポート名、接続、MCU の状態、起動 ID、`decode_errors` / `rx_error_count`。「USB には見えるのに応答しない」（Issue #11 の固まり）のときは、その旨と復旧手順（ハブの上流ケーブルを抜いて約 10 秒待つ）。未登録の個体と入れ替え（§6）。
2. **校正**: 「座席が空・手が離れている」のチェックを入れないと押せない校正ボタン（全軸 / 軸ごと。電源担当軸を含む必要がある: `power_axis_required`）。進行（CALIBRATING）と中止。結果は 3 軸の行程を前回の値と並べ、±30 以内かを判定語で。判断: 前回の値は設定の `mechanical_max_count - mechanical_min_count` を使う。
3. **反映と宣言**: §6 の 1・2。
4〜6. 監視画面と同じ部品（リミット、ゲームとの接続・履歴、短い動作）。

## 8. 両方の画面に出す部品（4〜6）

- **リミット**: `motion_limits` の `effective` / `requested` / `ceiling` / `operator_max` / `game_fields` / `limited` / `reasons` を 4 項目（gain・速度・加速度・Duty 上限）ごとに並べ、「ゲームが書いた値か」「どの上限で頭打ちか」を出す。変更は `POST /v1/limits`。
- **ゲームとの接続**: セッション ID（status の `source_session_prefix`、先頭 8 桁。完全な id は status に出さない既存の約束を守る）、鮮度（`fresh`、`source_age_ms`）、最後の `seq` / `frame_seq`、`requested_pose`、`effective_gain`。
- **コマンド履歴**: `GET /v1/events` を `after` で追い、新しい順の一覧（時刻・種類・要約）。ユーザーが過去を読んでいる間はスクロールを奪わない。
- **短い動作**: 中立へ（`/v1/center`）、ARM、DISARM、非常停止（`/v1/stop`）、異常リセット（`/v1/fault/reset`）。動かす操作（中立へ・ARM）は確認を挟む。

## 12. API の取り決め（PR 1 で足す。画面はこれを前提に、無ければ従来の手順を案内する）

- `POST /v1/calibration/apply` `{"axis": N}`: その軸の最新の CAL_RESULT（OK）を反映（§6 の 1。余裕を保つ）。条件を満たせば宣言を引き継ぐ（§11 の 3）。応答 `{"ok":true,"axis":N,"stroke":S,"prev_stroke":P,"within_tolerance":bool,"calibration_valid":bool,"path":"…","backup":"…"}`。断る理由: `not_disarmed` / `no_calibration_result` / `no_config_path` / `invalid_result`。
- `POST /v1/calibration/declare` `{"axis": N}`: `calibration_valid = true` を保存・反映。
- `POST /v1/units/assign` `{"axis": N, "device_id": "5131…", "confirm_suffix": "8D58"}`: 入れ替え（§6 の 3）。`confirm_suffix` が device_id の末尾 4 桁と一致しなければ 400 `confirm_mismatch`。
- `POST /v1/operator/hold`（Stop も行う）/ `POST /v1/operator/release`: オペレーター停止。hold 中は、`X-H3-Operator: 1` ヘッダの無い `/v1/arm` `/v1/start` `/v1/fault/reset` を 409 `operator_hold` で断る（画面はヘッダを付ける。loopback だけの約束で、認証ではない）。
- status に追加: `operator_hold: bool`、`unregistered_units: [{port, usb_serial, device_id}]`、`axes[].config_stroke`（設定の `mechanical_max − mechanical_min`）、`config_path`（設定ファイルから起動していれば）。
