# 実機の記録（2026-11-01、CoreS3 ×3 を h3-control-server に初めて接続）

構成: CoreS3 SE ×3（1C:DB = #1 電源担当、68:EE = #2、30:ED = #3）、Base15 DC 給電、USB は USB3.2 ハブ経由（`/dev/cu.usbmodem2141xx`）、モーター用 24V あり、無人、物理非常停止あり。サーバーは `control-server/config/bringup.toml` を元にした設定（ポート・`calibration_valid` を実機に合わせたもの）。ファームは `moter-controler` の env `m5stack-cores3-v1`。

## 通ったこと

| 項目 | 結果 |
| --- | --- |
| HELLO → 軸の割当 | 3 台とも初回で `selected_axis` 1 / 2 / 3 として識別。NVS の系統選択は 10/31 のまま |

## 止まったこと・直したこと

1. **START が `BAD_STATE`**（期限 50 ms 内の SET_POSITION が無い）。ファームが USB の受信を画面描画と同じ loop() で行い、描画（数十 ms）の間に受信が止まっていた。→ 描画を 100 ms に 1 回に間引き、描画の前後で受信、サーバー側の `set_position_valid_for_ms` 50 → 100、`mcu_command_timeout_ms` 100 → 200、`axis_status_timeout_ms` 200 → 300。
2. USB を FreeRTOS の専用タスクにする試み（2 回とも不採用）:
   - Core 0 のタスクから `Serial.write`: 状態変化で ACK と STATUS を続けて送る瞬間に PC 側で CRC 不一致（`decode_errors`）。ARM_PREPARE / HOST_FAULT の ACK が落ちて `ack_timeout`。
   - Core 1 のタスク: ARM → HOLDING は 0.6 s で成功・CRC エラー 0。しかし HOLDING の約 3 s 後に **2 台同時に USB 無応答**（HELLO にも esptool にも答えない。画面は未確認）。
   → loop() 方式に戻した。
3. **USB 無応答からの復帰**: Base15 の DC を切っても CoreS3 は USB ハブの VBUS で動き続けるので再起動しない（`ioreg` の USB sessionID が変わらない）。**ハブの上流 USB ケーブルを抜き差し**して再列挙させると、3 台とも esptool・HELLO に応答した。
4. 管理トークンは既定で不要に（`server.require_admin_token = false`、loopback 専用）。
5. テストページの「タブ非表示で送信停止」を撤去（運用上は別ウィンドウを前に出す。隠れたタブはタイマーが間引かれ `frame_seq` が進まなくなるので、サーバーの鮮度切れで減速停止する）。
6. 実機が足りないときに軸を模擬軸で埋める `sim_axes`（`[backend]`、serial backend）。#3 を別件で外している間、軸 3 を模擬軸にしてロール／ピッチの確認に進めた。

## 数値

## 追記（同日夕方〜夜）

- **KEEP_POWER 付きの 3 軸校正**: #1（電源担当）が自分の校正後も主電源を保持し、#2 の完了を待って切る動きを実機で確認。#1 5556 / 2778、#2 5507 / 2753（`/v1/calibrate` → `/v1/calibration/export`）。
- **#2 が動かなかった原因**: Grove Port.B の**接触不良**。MD13S の信号側 `DIR` を測ると、差し直す前は数 mV のまま、差し直した後は + で 0 V / − で 3.3 V と正しく切り替わり、その後は 30 % で正常に動いた（190 → 2153 count、上昇、記録どおり速度 − で上昇・カウント増）。途中で見えた「S −100 で 1636 → 191」はブレーキ解除時に座席が自重で落ちたもので、モーターは動いていなかった。
- **#3**: MD13S に 24V が来ていない（電源 LED 消灯）。配線の確認待ち。
- **切り分けで試した手段**: 従来 env の手動速度（無パルス停止あり）、試験専用 env `m5stack-cores3-noguard`（無パルス停止なし。機構の近くに人がいないときだけ）、#1 だけ実機で ARM して主電源を保持（`sim_axes = [2, 3]`）、MD13S の `DIR` 電圧（+ で 0 V、− で 3.3 V が期待値）。
- **START → ACTIVE を実機で初めて確認**（#1 / #2 実機、#3 模擬軸）。その後の停止は FAULT ではなく `SOURCE_STALE`（ブラウザのタブが裏に回ってタイマーが 1 Hz に間引かれ、frame_seq が進まなくなった）。→ テストページの 50 Hz 送信を Web Worker に移した。
- `frame_skew` 7 フレームで FAULT（USB の遅延揺らぎ status_age 2〜80 ms と模擬軸の混在）→ bring-up 設定は `max_frame_skew = 25`。
- gain 0.05 では目標の変化が中立から ±60 count 程度で「ビクッ」と動くだけ。gain を上げるには「動きの制限」の max_gain（既定 0.15、上限 1.0）を上げる。
- **主電源リレーは 3 軸共通で #1 の G2 が操作する**（architecture.md）。#2 の画面の R=1 ではリレーは入らない。切り分けで何度か「主電源なしの試行」をしてしまった。
