## 別の PC で立ち上げる手順

1. `git checkout expo-freeze-20261105`（または main の 2a11164）。
2. ポートを調べる: `ioreg -r -c IOUSBHostDevice -l | grep -E '"USB Serial Number"|"IOCalloutDevice"'`。並びは **#1 = 1C:DB:D4:BA:8D:58（主電源担当）、#2 = 68:EE:8F:D8:42:F0、#3 = 30:ED:A0:0B:20:40**。設定の `ports` をこの順に直す。
3. `cd control-server && cargo build`、`target/debug/h3-control-server check-config <設定>`、`target/debug/h3-control-server --config <設定>`。
4. `GET /v1/status` で 3 台とも `connected` と `fw_limits.stop_acc_count_s2 = 20000` を確かめる（0 ならファームが古い。ARM できない）。
5. 座席を空けて `POST /v1/calibrate {"axes":[1,2,3]}`。`rig_state` は校正中も CALIBRATION_REQUIRED のままなので、`/v1/events` の `cal_result` が 3 件そろうのを待つ。そのあとサーバーを再起動する（calibration_stale）。
6. flight_circus のゲームサーバー（`node server.js 8000`）を起動してゲームを開く。乗るときは非常停止の係を別に付ける。

## 運用の注意（未解決のもの）

- **物理の非常停止は #1 / #2 だけ**に配線。#3 はサーバーが協調停止する（11-03 の試験で 0.1 s）。
- 非常停止を画面で外したあと、サーバーの `POST /v1/fault/reset` が別に要る（展示モードではゲームが自動で解除する）。直す PR #78 は Codex レビューで「焼かない」、修正待ち。
- 3 台同時の USB 無応答（Issue #11）: ハブの上流を抜いて約 10 s 待って差し直す → ポートを調べ直して設定を直す。
- CoreS3 が電源ボタンで起動しないままになることがある（Issue #68）。立ち上げ時に 3 台の画面がついているか見る。
- #2 が下りの全速で急に止まる（11-03 に 4 回、FAULT にはならず 0.3〜0.5 s で戻る）。原因不明。
- ゲームサーバーの展示モードは、タブを閉じても ARM を見つけると STOP を送る。手で ARM して保持したいときはゲームサーバーを止める。
